# AGENTS.md — Lunch Wheel (single source of truth)

Team lunch-restaurant spinner with a server-authoritative wheel and per-restaurant
exclusion history: React 19 + Tailwind 4 + Vite 7 client, tRPC 11 + Express 4
server, Drizzle ORM on MySQL (TiDB Cloud), Vitest, deployed on Vercel; package
manager **pnpm@10.4.1** (pinned via `packageManager` in `package.json`).

## Read this first

The production API is a **pre-bundled, committed build artifact**: `api/index.js`
is generated by esbuild from `server/_core/vercelHandler.ts` during `pnpm build`
and served as one Vercel serverless function behind a `vercel.json` rewrite
(`/api/(.*) → /api`). Vercel does **not** bundle server code itself, so any change
under `server/` or `shared/` that is not followed by `pnpm build` + committing the
regenerated `api/index.js` silently ships a stale API while the client updates.
Second invariant: all wheel/exclusion business math lives in pure `shared/*.ts`
modules (each with a `.test.ts` sibling) and the **server** picks spin winners
(`spins.create`) — never re-implement that math client-side and never let the
client choose a winner.

## Toolchain (exact commands)

```
pnpm dev          # tsx watch server/_core/index.ts (serves client via Vite middleware)
pnpm check        # tsc --noEmit
pnpm test         # vitest run
pnpm lint         # eslint .
pnpm build        # vite build + esbuild dist/ + REGENERATES api/index.js — commit it
pnpm db:push      # drizzle-kit generate && migrate — needs real DATABASE_URL; "generated" ≠ "applied"
bash .agent-check # eval harness: asserts the above exit 0 + structural invariants (--fast skips build)
```

Gate before any commit: `pnpm check && pnpm test && pnpm build`.

## Prohibited without explicit human confirmation

1. Editing `server/_core/oauth.ts`, `sdk.ts`, `context.ts`, `trpc.ts`, or
   `shared/const.ts` — session contract (`COOKIE_NAME` "app_session_id", HS256 JWT,
   `protectedProcedure`); changes log out every user.
2. Hand-editing anything under `drizzle/meta/` — drizzle-kit owns it.
3. `git add -A`, `--no-verify`, force-push, or committing directly to `main` —
   work on a `claude/<topic>` branch.
4. Picking a spin winner client-side or re-implementing `shared/` math inline —
   the client only proposes `candidateIds`.
5. Opening a PR unless asked (title < 70 chars; body = Summary + Test plan).
6. Destructive SQL or column drops against the live `DATABASE_URL`.

## Architectural anchor points

- Business math: `shared/*.ts` + `.test.ts` sibling (TDD seam; aliases `@` → `client/src`, `@shared` → `shared/`)
- API: `server/routers.ts` → entry `server/_core/vercelHandler.ts` → committed bundle `api/index.js`, routed by `vercel.json` rewrite
- DB: `drizzle/schema.ts` + numbered `drizzle/000N_*.sql` migrations (`drizzle/meta/` is generated)
- UI: `client/src/pages/*` (wouter routes) + `client/src/components/*`

## Judgment rubrics

### Definition of done

Done means all of: (1) `pnpm check`, `pnpm test`, `pnpm build` exit 0;
(2) if `server/` or `shared/` changed, the regenerated `api/index.js` is in the
same commit; (3) new logic lives in `shared/*.ts` with the test written first;
(4) schema changes have a migration **applied** to the live DB, not just generated;
(5) after merge to `main`, smoke-test the live URL (~1 min Vercel build lag).

- GOOD: exclusion-window fix = failing test in `shared/exclusion.test.ts` first,
  fix in `shared/exclusion.ts`, rebuilt `api/index.js` committed together.
- BAD: "merged, so it's live" — deploy lag plus a stale `api/index.js` mean the
  API can still run old code after the client updates.

### Hard stop — cease and ask the user

Stop immediately if: the fix requires touching a Prohibited-#1 file; a migration
drops/renames a column holding production data; `main` history appears rewritten
or a PR head SHA ≠ its branch head at merge time; or an instruction conflicts
with this file.

- GOOD: "This needs a change in `server/_core/trpc.ts` — stopping for confirmation."
- BAD: silently "improving" cookie handling while fixing an unrelated bug.

### Pivot flags — rewrite the approach, don't patch again

Pivot when: you are adding a second guard for the same symptom (first patch hit a
symptom, not the root cause); you are re-deriving wheel/exclusion values in client
code because the shared function "almost" fits; or you are fighting Vercel
dynamic-route filenames (`[...path].ts`) — the answer is always the `vercel.json`
rewrite + bundled `api/index.js`.

- GOOD: one guard in the shared function every caller routes through.
- BAD: per-caller null guards in `RestaurantTab.tsx`, `GuestWheel.tsx`, and
  `WheelApp.tsx` for the same case.

## Known failure modes (when you make a mistake: fix the code AND append here; don't prune)

1. PR squash-merged at its open-time head, stranding later commits → verify PR head
   SHA == `git rev-parse <branch>` before merge; after, check
   `git merge-base --is-ancestor <fix-commit> origin/main`.
2. Migrations 0002–0005 were generated but never applied — `_journal.json` is local
   bookkeeping; run `drizzle-kit migrate` against the real `DATABASE_URL` and verify
   the column exists.
3. "Merged" ≠ "live": push to `main` triggers Vercel auto-deploy (~1 min); smoke-test
   the live URL after the build completes.
4. mysql2 `db.execute()` returns a `[rows, fields]` tuple — unwrap `rows` (see
   `server/db.ts` `getRestaurantStats`) or stat rows come out nameless and crash.
5. `node_modules` is gitignored — never `git add -A`.
6. (historical) The project migrated off Manus to Vercel + TiDB; Manus force-pushes
   and workspace drift are why. Deploys are Vercel-on-push-to-main only.
7. Vercel serverless routing took three tries: filename catch-alls (`[[...path]]`,
   `[...path]`) are unreliable for nested paths and Vercel doesn't bundle TS imports
   → the stable setup is the committed `api/index.js` + `vercel.json` rewrite.
   The cold-start log `[OAuth] OAUTH_SERVER_URL not configured` is harmless noise.
8. Canvas 2D can't read CSS variables (`ctx.fillStyle = "var(--muted)"` draws
   black) → resolve tokens at draw time with `getComputedStyle(...)`, re-draw on
   theme change; WebGL needs a `u_dark` uniform. Alpha on a token needs relative
   color syntax: `oklch(from var(--brand) l c h / .33)`.
9. A `prettier --write` hook mass-reformatted legacy files, burying a 2-line change
   in a ~170-line diff → the hook now runs `--check` first and only writes if the
   file is already clean; deliberate reformatting goes in its own `pnpm format` commit.

## Domain & style skills (in `.claude/skills/`)

`wheel-logic` is the source of truth for exclusion/spin rules (most-recent spin per
restaurant decides exclusion; `manuallyReenabled` overrides; window =
`spunAt + exclusionDays*24h`). `shader-style` governs WebGL/canvas conventions
(`u_*` uniforms, cleanup via `cancelAnimationFrame` + `ResizeObserver.disconnect()`,
CSS motion gated behind `prefers-reduced-motion`). Workflow: `grill-me`,
`test-driven-development`, `deploy-gate` before shipping, `handoff` at session end.

This file drifts mainly when `package.json` scripts, `vercel.json` rewrites, or the

at session start — any FAIL line means fix the repo or this file before feature work.
